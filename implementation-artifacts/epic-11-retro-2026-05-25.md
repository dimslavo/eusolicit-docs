### BLOCKER 1 — ESPD XML Non-Conformance

**File:** `espd_service.py` lines 299, 349
**Severity:** P0-gate-blocking | Risk: E11-R-002 | AC: AC-6.7.2

Current implementation generates ESPD XML with internal custom namespace `urn:X-eusolicit:espd:schema:v1`. The official EU ESPD EDM namespace is required. Invalid ESPD XML is rejected by EU procurement portals (TED, eTendering) — a bid-deadline data-loss scenario.

**Required remediation:**
1. Replace `ESPD_NS` with official EU ESPD EDM URI (https://github.com/ESPD/ESPD-EDM)
2. Align element names (`ESPDResponse`, Part elements) to official schema
3. Add `lxml` XSD validation to test suite (E11-P0-003)

### BLOCKER 2 — DOCX/PDF Event-Loop Blocking

**Files:** `grants_service.py` (`build_report_docx()`), `espd_service.py` (`generate_espd_pdf()`)
**Severity:** Architecture-violation blocking | AC: Architecture AC-6.3.2

Both `python-docx Document.save()` and `reportlab doc.build()` are CPU-bound blocking operations called from `async def` handlers without `run_in_executor`. Architecture explicitly requires: *"Export endpoints never block the FastAPI event loop (every WeasyPrint/python-docx call runs via `asyncio.get_running_loop().run_in_executor`)"*.

**Required remediation:**
```python
# Correct pattern:
async def export_reporting_template_docx(...) -> bytes:
    template = await generate_reporting_template(...)
    loop = asyncio.get_running_loop()
    return await loop.run_in_executor(None, build_report_docx, template)
```

Apply to ALL DOCX/PDF export handlers in both `grants_service.py` and `espd_service.py`.

## 7. Key Patterns Established in Epic 11

### E11-P01 — Agent Integration Pattern (Complete and Stable)
[PATTERN] All future agent integrations MUST use: `AiGatewayClient.run_agent(agent_name, payload)`, flat `{"message": "...", "code": "AGENT_UNAVAILABLE"}` 503 body via JSONResponse, `X-Caller-Service` header, `aigw_timeout_seconds` from settings, no client-side retry. Deviations (different error body shape, client-side retry, missing X-Caller-Service, direct AIGW URL construction) are blockers in review. S11.04 is the canonical backend reference.
IMPACT: `prompt_adjustment`
SEVERITY: `high`

### E11-P02 — Null vs. Empty List for Optional Response Fields
[PATTERN] For any response field that is a list AND whose absence has different UI semantics from an empty list, type must be `list | None` (not `list`). `null` = agent didn't generate (suppress component), `[]` = agent generated but empty (show empty state component). Preserved through Pydantic schema, parser function, and frontend conditional render. Must appear in the AC, schema, parser, and component.
IMPACT: `prompt_adjustment`
SEVERITY: `medium`

### E11-P03 — Migration Downgrade Multi-Row Safety
[PATTERN] Any migration downgrade that recreates a UNIQUE or PK constraint must include a regression test inserting ≥2 rows with the same grouping key before downgrading. The test asserts the downgrade completes without constraint violations. Unit tests with single rows per grouping key miss this class of production bug entirely. Reference: S11.01 `ROW_NUMBER() OVER (PARTITION BY company_id ORDER BY created_at)`.
IMPACT: `standards_update`
SEVERITY: `medium`

### E11-P04 — Module-Level Arithmetic Tolerance Constant
[PATTERN] For EU grant or any financial calculation endpoint, define tolerance as a named module-level constant: `_ARITHMETIC_TOLERANCE = 0.01` (EUR). This makes the tolerance visible, testable, and discoverable via grep. Apply to any endpoint with float arithmetic on monetary values to prevent float precision failures without hiding real bugs.
IMPACT: `prompt_adjustment`
SEVERITY: `low`

### E11-P05 — Design System Component ATDD Source-Inspection
[PATTERN] Any AC specifying a component from `@eusolicit/ui` (e.g., `<Select>`, `<Dialog>`, `<Sheet>`, `<Tabs>`) must have a corresponding ATDD source-inspection assertion: `assert "<Select" in component_source and "from @eusolicit/ui" in component_source`. This catches design system violations at RED phase before review, not during review. Add to frontend ATDD checklist template for all stories specifying `<Select>`, `<Dialog>`, `<Sheet>`, `<Tabs>`, `<DatePicker>`.
IMPACT: `standards_update`
SEVERITY: `high`

### E11-P06 — 503 Agent Error Body Assertion Template
[PATTERN] All agent integration tests asserting 503/AGENT_UNAVAILABLE responses must use the template: `assert "message" in data and "code" in data and "detail" not in data`. Include a comment quoting the exact AC JSON shape. `data["detail"]` is the FastAPI HTTPException detail key — flat JSONResponse bodies from agent error handlers never use it. Any test asserting `data["detail"]` is asserting the wrong structure.
IMPACT: `standards_update`
SEVERITY: `high`

### E11-P07 — Hook Reuse Before Duplication
[PATTERN] Frontend stories implementing a second panel of the same feature domain MUST audit existing hooks from the prior domain story before creating new ones. `useComplianceFrameworks` and `useComplianceFramework` (S11.14) were reused directly in S11.15 without modification — this produced a first-pass APPROVED story with zero blocking items. Document reused hooks explicitly in Dev Notes.
IMPACT: `prompt_adjustment`
SEVERITY: `low`

### E11-P08 — KB-Grounded Agent Integration Test Pattern
[PATTERN] Integration tests for KB-grounded agent endpoints (ESPD auto-fill, grant eligibility) require: (1) `aigw_env_setup` session-scoped autouse fixture setting `CLIENT_API_AIGW_BASE_URL` to a respx-interceptable URL; (2) `kb_grounded_test_data` fixture creating Company + User + SirmaAIProject + SirmaAIKbFile; (3) respx mock on `{aigw_base_url}/agents/{agent_name}/run`; (4) assertion that final endpoint output reflects grounded content from mocked agent response. Reference: `tests/integration/test_kb_grounded_agents.py` (S11.23).
IMPACT: `standards_update`
SEVERITY: `medium`
