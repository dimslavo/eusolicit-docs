## Part 1: Epic 14 Review

### What Went Well

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: medium`  
**Carry-forward codification in Dev Notes** — Story 14.4 explicitly inherited and named the anti-patterns from 14.1, 14.2, and 14.3 by story number (e.g. "Epic 14.2 BLOCKING #3 — do not rebuild bespoke test fixtures"). This is the first epic where a story's Dev Notes read like a living runbook of what NOT to do based on that same epic's earlier failures. The pattern reduced per-story repeat-violations in 14.4 significantly.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: medium`  
**Partial-unique index for idempotent invite semantics** — Stories 14.1 and 14.4 both independently applied the `UNIQUE (col1, col2) WHERE <predicate>` pattern (active workspace name uniqueness; active external invite by proposal+email). The `IntegrityError → 409` translation is now consistent across three stories. This is the correct form for soft-delete–aware uniqueness constraints. Reference: migration 046 `ix_client_workspaces_company_name_active`, migration 048 `ix_external_collaborators_active_email`.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: medium`  
**External JWT claim-shape isolation** — Story 14.4 correctly isolates external collaborator tokens from regular `CurrentUser` tokens by deliberately omitting `company_id` and `subscription_tier` claims. `get_current_user` rejects the token with a `KeyError → 401` before any auth logic runs. This is a zero-cost isolation primitive that prevents claim collision without an additional auth middleware layer. `ExternalCollaboratorPrincipal` as a separate dataclass (non-subclass) makes the type system enforce non-substitutability.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: medium`  
**Single-use semantics via `accepted_at` DB stamp** — Story 14.4's `accepted_at IS NOT NULL → 410 Gone` pattern mirrors Epic 8's `webhook_events.event_id` unique-constraint idempotency. Subsequent accept calls on the same JTI return a distinguishable 410 (not 401 or 409), making the client error response semantically correct. Reference: AC 4, `external_collaborator_service.accept()`.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: high`  
**Stripe seat isolation contract enforced at table level** — Story 14.4 AC 9 mandates that `count_active_seats()` only queries `company_memberships`, never `external_collaborators`. A dedicated integration test (`test_external_invite_does_not_consume_stripe_seats`) and a Stripe-mock test (`test_report_seat_count_to_stripe_uses_active_members_only`) create a regression guard for FR8.5. This "table-as-contract" pattern prevents billing drift caused by future schema changes that join the two tables.

**[PATTERN]** `IMPACT: prompt_adjustment` `SEVERITY: medium`  
**Workspace re-validation on every external read** — Story 14.4's `_verify_external_proposal_match` helper re-checks `proposal.workspace_id == principal.workspace_id` on each request. If a proposal is administratively re-assigned to a different workspace, the old token immediately returns 404 (existence-leakage protection). This prevents stale tokens from granting access after workspace restructuring.

### Challenges and Anti-Patterns

**[ANTI-PATTERN]** — `[ACTION]` `IMPACT: standards_update` `SEVERITY: critical`  
**Bespoke test fixtures rebuilt in every single story (5/5)** — Despite AC-level prohibition in 14.2 Dev Notes and explicit carry-forward in 14.4 Dev Notes, EVERY story in Epic 14 was flagged for bespoke test fixture construction:
- 14.0: pre-existing `ScopeMismatch` fixture issue in `test_002_migration.py` (not directly caused, but evidence of fixture fragility).
- 14.1: built its own `setup_tenant` + JWT helper instead of `register_and_verify_with_role`.
- 14.2: rebuilt `_register_and_verify_with_role`, used `ASGITransport(app=fastapi_app)` directly, used `db_session` (no rollback) instead of `client_session`.
- 14.3: 30+ test files required path-refactoring fixes from structural changes.
- 14.4: `workspace_setup` / `cross_tenant_setup` / `client_committing` are locally-composed rather than root-conftest fixtures.

Root cause: dev agents default to building the simplest local fixture rather than learning the project's established `eusolicit-test-utils` helpers. The canonical helpers (`register_and_verify_with_role`, `create_company_pair`, `client_session`) need to be visible at the moment the agent writes the first test line — not buried in a "References" section.  

**Fix:** Add a mandatory preamble block to the dev-story template's Testing Requirements section that pastes the canonical fixture imports and usage example. Make non-use a BLOCKING code review finding category.

**[ANTI-PATTERN]** — `[ACTION]` `IMPACT: standards_update` `SEVERITY: critical`  
**Story file `review` status ≠ sprint-status `done` on 4 of 5 stories** — At epic close-out, sprint-status.yaml shows all 5 stories `done`, but story files show:
- 14-0: `Status: review` (approved Round 4, but story file not updated to `done`)
- 14-1: `Status: review` (approved after rework, but story file not updated)
- 14-2: `Status: done` ✅
- 14-3: `Status: review` (review approvals in child sections, status field not updated)
- 14-4: `Status: review` (approved after review-fix pass, status field not updated)

This is the **3rd consecutive epic** with this anti-pattern (E12, E13, E14). The orchestrator story-close workflow MUST cross-check story file `Status:` field before writing `done` to sprint-status. A `done` story with `Status: review` in its file is a quality gate breach.

**Fix:** Orchestrator story-close: `grep "^Status:" {story_file}` must return `done` before sprint-status update. If not, auto-set status or HALT.

**[ANTI-PATTERN]** — `[ACTION]` `IMPACT: standards_update` `SEVERITY: critical`  
**Documentation-vs-code mismatch: claimed fix, code unchanged** — Story 14-0 Round 3 completion notes claimed CTE tie-breaking (`NULLS LAST, company_id ASC`) was applied, but the migration SQL still had `ORDER BY invited_at ASC` only. This required a Round 4. Story 14-2's Dev Agent Record claimed a 60-case parametrized matrix (`test_rbac_permission_matrix`) exists, but the traceability matrix audit found only 2 tests on disk in `test_workspace_rbac.py`. This is a **false completion claim** that propagated to sprint-status `done`.  

This is the same anti-pattern as E13's "Review approval without quoted test execution output" but in reverse: the dev agent's written claim is trusted without the reviewer searching for the code artifact.

**Fix (two-pronged):**
1. Code review template MUST require reviewers to `grep` for every file explicitly listed in the Dev Agent Record's File List and confirm the function/class exists.
2. Completion notes claiming a test exists MUST include a verbatim `pytest -k <test_name> -v` output showing the test ran (not just "all tests pass").

**[ANTI-PATTERN]** — `[ACTION]` `IMPACT: prompt_adjustment` `SEVERITY: high`  
**Breaking API changes without caller migration (repeated from E13)** — Story 14.2 made `ProposalCreateRequest.workspace_id` required (no default) without updating any existing proposal-creation callers. The in-story test suite (`5 passed`) didn't surface the regression because it only tested the new RBAC logic. `test_proposal_collaborators_audit.py` and other existing suites would have failed. This is a **scope-creep / regression risk** pattern: when a shared schema changes, the implementing agent only runs tests for the new story, not the full service suite.

**Fix:** Any story that modifies a `Request` schema shared by existing endpoints MUST run `make test-service SVC=<service>` (full suite) in the same session before marking review-ready. Add to dev-story template as a conditional gate: "If you modified any schema file in `schemas/`, paste the full service test suite result."

## Key Lessons for Subsequent Epics

1. **Test canonical fixtures ARE the standard — deviation is a BLOCKING finding.** The dev-story template must embed the import block for `register_and_verify_with_role`, `create_company_pair`, `client_session`. Zero tolerance.

2. **Claimed test exists → paste `pytest -k <name>` one-liner output.** Not "all tests pass." The specific test by name.

3. **Story file `Status:` is updated to `done` by the dev agent in the same session as the final review approval.** Not by the orchestrator post-hoc. The dev agent reads the approval, then edits the story file header.

4. **TEA review is a story AC, not an injected story.** It runs before senior code review. Score ≥ 80/100 is required.

5. **Review-fix passes run the full service smoke test before claiming complete.** `python -c "from <service>.main import app"` + `make test-service SVC=<service>`. This is non-negotiable.

6. **E13 carry-forwards block new feature epics past E15.** This is an explicit decision recorded in this retrospective.
