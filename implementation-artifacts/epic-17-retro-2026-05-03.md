**CRM Adapter Registry with `@register_adapter` decorator — stub-first extensibility.** `CRMAdapter` ABC defined in 17.0; `StubAdapter` registered for every provider; real adapters in 17.1/17.2/17.3 replace stubs via the decorator without changing the dispatcher (`forward.py`). **[PATTERN]** `IMPACT: standards_update` `SEVERITY: high`
**Three-tier circuit-breaker hierarchy for CRM.** (1) `crm:{workspace_id}:{provider}` — per-workspace per-provider transient-failure breaker; (2) `crm:auth:{provider}` — provider-global OAuth client outage breaker; (3) `crm:quota:{workspace_id}:salesforce` — Salesforce daily-quota exhaustion breaker (independent from transient failures). Each breaker opens independently so W1's HubSpot outage does NOT affect W2's HubSpot connection. This is the most precise breaker scoping in the codebase to date. Reference: 17.0 §4.2, 17.3 AC-1 §5.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: high`
**Tier-paused fail-CLOSED webhook contract.** A downgraded workspace receives `200 {"status": "tier_paused"}` (NOT 402) from the webhook handler; a `sync_logs` row with `auth_failed` / `tier_downgraded` is written; the tier resolver defaults `None → 'starter'` on schema-availability outage (fail-CLOSED). This is distinct from the connect endpoint's 402 (user-facing, interactive) vs the webhook handler's 200+tier_paused (provider-facing, silent). Reference: 17.1 §8.12, 17.2 AC-6 §5, 17.3 AC-8 §5.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: medium`
**Runtime default-stage seed at OAuth callback, not in migration.** Default CRM stage mappings are seeded per-workspace at OAuth callback time via `INSERT ... ON CONFLICT (workspace_id, provider, eu_solicit_status) DO NOTHING` inside a `session.begin_nested()` SAVEPOINT. The migration creates the table structure only — no workspace-specific rows. Re-connection is idempotent. Admin-api `reset-to-default` route uses a per-provider default-mapping registry dict. Reference: 17.1 AC-5, 17.2 AC-5, 17.3 AC-6.

**[PATTERN]** `IMPACT: prompt_adjustment` `SEVERITY: medium`
**Cross-portal forged webhook detection must log at WARNING — silent drop hides hostile activity.** When a webhook carries a `portalId`/`company_id` that matches W1's connection but a `deal_id` whose internal `crm_external_ref` mapping belongs to W2, the correct response is `200 "ignored"` AND a structured `crm.webhook.cross_portal_attempt` WARNING-level log with `{attempted_portal, attempted_deal_id, owning_workspace}`. **[PATTERN]** `IMPACT: standards_update` `SEVERITY: medium`
**Salesforce daily-quota state machine — Redis-Lua with midnight-UTC auto-rollover.** `_SALESFORCE_QUOTA_LUA` in `core/rate_limit.py` is atomic: GET → threshold check → INCR+EXPIRE on `ok`/`warning`; no INCR on `exhausted`. Key TTL = `seconds_until_next_midnight_UTC` so the key auto-expires at rollover. `crm:quota:{workspace_id}:salesforce` breaker `reset_timeout` matches the same value so it auto-half-opens at midnight. `Sforce-Limit-Info` header is observational-only (org-wide, not per-integration); our Redis counter is authoritative for our usage. Reference: 17.3 AC-4.

**[PATTERN]** `IMPACT: prompt_adjustment` `SEVERITY: medium`

Each adapter's `authenticate()` docstring must cross-reference the other two providers' styles. Reference: 17.1 AC-2 §1c, 17.2 AC-2 §2c, 17.3 AC-2 §2.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: medium`
**Webhook subscription lifecycle for subscription-model providers (Pipedrive pattern).** On OAuth callback success: `POST {api_domain}/v1/webhooks` to register subscription; persist `provider_webhook_id` on `crm_connections` row. On `status → revoked`: fire-and-forget `DELETE {api_domain}/v1/webhooks/{provider_webhook_id}`; log WARNING on failure (NOT ERROR — provider may already revoke server-side). Subscription registration failure is graceful-degradation (connection committed, structured warning, real-time updates unavailable until admin re-registers). HubSpot's webhook config is portal-wide via marketplace app — no per-connection registration needed. Reference: 17.2 AC-7.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: medium`

1. **The ATDD un-skip step is the missing last mile.** Dev agents implement ACs and quote passing pytest summaries — but never return to un-skip the formal ATDD RED-phase scaffolds. This is fixable with a one-line addition to the completion checklist.
