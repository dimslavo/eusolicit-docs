## Part V — Patterns Confirmed in Epic 13

### P13-01: NFR hot-fix + proper hardening story workflow

Commit `2d41fcf` made a minimal inline fix to unblock the NFR HALT assessment on the same day it ran. The full implementation story (7-17) was created in parallel and delivered the proper refactored solution. This two-step pattern is the correct E07-class NFR FAIL response:
- Step 1: Emergency inline patch (unblocks the halt signal; no tests required)
- Step 2: Proper story with full ATDD coverage (closes the hardening debt properly)

Apply to all future NFR FAIL findings on existing endpoints.

### P13-02: `asyncio.CancelledError` requires explicit handler (Python 3.8+)

`CancelledError` inherits from `BaseException` (not `Exception`) in Python 3.8+. A bare `except Exception:` block silently drops cancellation signals, leaving coroutines with partially-committed state and no cleanup. Required pattern in any `async` function using `async with` or `finally`:

```python
try:
    ...
except asyncio.CancelledError:
    # explicit cleanup or re-raise
    raise
except Exception as exc:
    # application error handling
```

Add to ATDD checklist for any story that introduces `async` functions with cancellation-sensitive paths.

### P13-03: structlog stdlib routing is required for pytest `caplog`

`structlog.PrintLoggerFactory()` (the dev/test default) bypasses stdlib `logging.Logger`. `pytest`'s `caplog` fixture captures only stdlib records. Without routing, assertions on log output will always fail silently (no captured records). Canonical fix in `conftest.py`:

```python
@pytest.fixture(scope="session", autouse=True)
def configure_structlog_stdlib():
    structlog.configure(logger_factory=structlog.stdlib.LoggerFactory())
```

This fixture is now mandatory in every service's `tests/conftest.py`. (Story: 7-17 Task 5.9)

### P13-04: Migration spec contradiction ("no migration needed") is a predictable failure

Story headers often claim "No schema migration needed" based on assumptions about the target schema. E13 Story 7-17 required migration 025 because `shared.audit_log` was missing `company_id` and `correlation_id` columns, despite the story claiming no migration. Resolution: spec writers must run `grep -r "column_name" services/*/alembic/versions/` and inspect the ORM models before writing "no migration needed". Add to story template: "Migration required? [YES/NO — confirmed by grepping target schema models]"

### P13-05: Fire-and-forget audit write canonical form (E13 authoritative)

The canonical pattern for audit writes off the TTFB path (Rule 45):

```python
async def _write_generation_audit(session, *, proposal_id, user_id, company_id,
                                   ip_address, correlation_id, before_snapshot):
    try:
        async with session.begin():
            # write exactly one audit row with full terminal outcome
            ...
    except Exception as exc:
        structlog.get_logger().error("audit_write_failed",
                                     proposal_id=str(proposal_id),
                                     correlation_id=correlation_id,
                                     exc_type=type(exc).__name__)

# In the request handler / background task finally block:
asyncio.create_task(_write_generation_audit(
    session=session,
    proposal_id=...,
    ...
))
```

Rules: (1) task owns its own `async with session.begin()` — never shares the endpoint session, (2) catches all exceptions and logs at ERROR — never propagates, (3) scheduled in `finally` block so cancellation paths are also audited, (4) `after` field populated from the terminal outcome known at finally time.

Prior forms using `await write_audit_entry()` + `await session.commit()` inline are prohibited on the TTFB path (Rule 45).

### P13-06: Coordinator story pattern for multi-concern hardening epics

When a hardening epic has 3+ independent sub-stories, introduce a coordinator story that:
- Delegates narrow technical slices to sub-stories (each with its own AC set and tests)
- Owns cross-cutting acceptance criteria that can only be verified after sub-stories complete
- Functions as the close-out gate (AC6 in drift-recovery-story)
- Prevents single mega-stories with 10+ ACs and long review cycles

Apply to any future epic with 3+ independent work streams under a shared quality umbrella.

### P13-07: Hot-fix context section in story Dev Notes

Any story that implements full hardening on top of an emergency inline fix must include a "Hot-Fix Context" section in Dev Notes specifying:
- Commit SHA and message of the pre-applied fix
- Exact files and lines changed by the hot-fix
- What is already done vs. what the story must add

This prevents dev agents from re-implementing already-merged changes (reference: 7-17 "Hot-Fix Context" section with commit `2d41fcf`).

## Part VI — Anti-Patterns Confirmed in Epic 13

### AP13-01: Dev session regression between review passes [ACTION]
IMPACT: standards_update | SEVERITY: critical

A new dev session modified a file touched in a prior approved review pass without reading the prior review's resolved findings first. This overwrote the fire-and-forget audit pattern (F4 resolved in 2nd pass) with a synchronous dual-write pattern, violating AC3 and causing 3 tests to fail.

**Required fix:** Add to dev-story template and code-review template: "Before editing any file that has prior review findings, re-read the current file state and list all resolved deviations that must be preserved."

### AP13-02: Review approval without quoted test execution output [ACTION]
IMPACT: standards_update | SEVERITY: critical

The 2nd-pass adversarial review approved Story 7-17 with "test_audit_log_row_has_correct_shape — PASS" without re-executing the test suite. The 3rd pass found 3 failures. Any review that claims "tests pass" or approves a previously-failing criterion MUST quote the actual pytest execution line (e.g., `3 failed, 16 passed in 12.4s`) in the review artifact. An approval without quoted execution output is invalid.

### AP13-03: sprint-status `done` set without cross-checking story file status [ACTION]
IMPACT: config_tuning | SEVERITY: high

Story 7-17 in sprint-status.yaml shows `done`; its story file shows `Status: review` with 3 blocking findings from the 3rd adversarial review. The orchestrator's story-close workflow must cross-check the story file `Status:` field before writing `done` to sprint-status.yaml. A story file at `review` with open blocking findings cannot transition to `done` in sprint-status.

### AP13-04: AC text not updated to reflect implementation-time schema choices [ACTION]
IMPACT: standards_update | SEVERITY: medium

AC1 specified `{"error":"ai_gateway_error","correlation_id":"..."}` but the implementation emitted `{"error": "<prose>", "code": "gateway_error", "correlation_id": "..."}`. The implementation chose "option (a)" — keep `{error, code}` shape and add `correlation_id` — but the AC text was never updated. Future reviewers will rediscover this as a spec violation. Rule: any implementation-time schema deviation from an AC must update the AC text in the story file before the review approves.

### AP13-05: Injected `inj-*` stories deprioritized behind feature work [ACTION]
IMPACT: config_tuning | SEVERITY: critical

Stories injected as carry-forward remediation (`inj-01`, `inj-02`, `inj-03`) sat at `ready-for-dev` through the entire E13 window while Epic 14 advanced. The orchestrator's injection mechanism creates stories but does not enforce execution order. Injected stories with `SEVERITY: critical` from prior retros must be the FIRST items processed in the next epic's execution queue — not appended to the backlog after feature work.

### AP13-06: Story header `Epic:` field misaligned with sprint-status assignment [ACTION]
IMPACT: config_tuning | SEVERITY: medium

`dw-01`, `dw-02`, `dw-03` story headers all read `Epic: Post-E07 cleanup (no assigned epic)` despite being assigned to Epic 13 in sprint-status.yaml. When a story is injected or reassigned to an epic, its header `Epic:` field must be updated immediately. Misaligned headers confuse downstream traceability tools and cause incorrect AC scope dating.

### AP13-07: Pydantic response schema uses bare `str` for enumerable status fields [ACTION]
IMPACT: prompt_adjustment | SEVERITY: medium

`ProposalDetailResponse.status` was `str` instead of `Literal["draft", "active", "archived"]`. Bare `str` prevents OpenAPI enum schema generation, allows unknown values to reach the frontend without validation, and loses machine-readable contract value. All Pydantic response schema string fields with a known value set MUST use `Literal[...]` or `StrEnum`. Add to backend story template.

### AP13-08: `asyncio.get_event_loop()` in Celery tasks (deprecated Python 3.12) [ACTION]
IMPACT: prompt_adjustment | SEVERITY: medium

`asyncio.get_event_loop()` is deprecated in Python 3.12. Celery tasks that bridge sync→async execution must use:
```python
loop = asyncio.new_event_loop()
try:
    result = loop.run_until_complete(async_fn())
finally:
    loop.close()
```
Never `asyncio.run()` (fails when a loop is already running) or `asyncio.get_event_loop()` (deprecated, emits DeprecationWarning, raises RuntimeError in 3.14+). Add to Celery task template and ATDD checklist.
