**[PATTERN]** `IMPACT: standards_update` `SEVERITY: high`
**NEXT_PUBLIC_ as vendor public site-key — intentional browser exposure with documented threat model.** Delighted's API key is browser-accessible via `NEXT_PUBLIC_NPS_DELIGHTED_API_KEY`. This is Delighted's published threat model (analogous to Google Analytics tracking ID — the key grants only survey delivery capability, no privileged access). The correct pattern for all future third-party vendor SDK site-keys: (1) expose via `NEXT_PUBLIC_` prefix if the vendor threat model designates it a public key, (2) document the exposure decision explicitly in §6 Known Deviations, (3) assert via source-inspection test that `eval(...)` is forbidden in the SDK init module, (4) scrub the setting name from structlog output (not the value, since it's public). Reference: S20-0 AC-9.2 D-12, AC-15 source-inspection.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: high`
**Lazy `await import(...)` is mandatory for all vendor SDK imports in Next.js.** `@delighted/web-sdk` is loaded via dynamic `import('@delighted/web-sdk')` inside an `async function` that only runs when the tier-gate passes. Static top-level `import` would ship the ~30KB bundle to ALL users (Free/Starter/Professional) regardless of tier-gate outcome. Pattern: `const delighted = await import('@vendor/sdk')` inside the init function, wrapped in `try/catch` that logs but does NOT throw (vendor-SDK crash MUST NOT break the workspace-page render). Reference: S20-0 AC-15.1, fence rows #9 and #10.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: high`
**DEFERRABLE INITIALLY DEFERRED constraint pre-check is required for webhook dedup idempotency.** When a UNIQUE constraint is declared `DEFERRABLE INITIALLY DEFERRED`, `IntegrityError` fires at COMMIT, not at flush — the route handler has already returned by then, so catch-and-map logic is unreachable. Correct pattern: add a pre-INSERT `SELECT` short-circuit (`select(Model).where(unique_col == value)`); if found, return 200 immediately before INSERT. The DEFERRABLE constraint remains in the schema as defence-in-depth for the transaction-commit layer. A naive `INSERT ... ON CONFLICT DO NOTHING` doesn't return the existing row, so it can't populate the response body. Reference: S20-0 D-17, `nps_feedback.py` lines 315–326.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: high`
**Workspace-scope BEFORE tier-gate in Depends order prevents 402 revealing tier information on cross-tenant attacks (AP14-04 refinement).** `require_workspace_role(...)` must be the first dependency, `require_pro_plus_tier` second. A Free-tier user attacking Company B's workspace must receive 404 (workspace not visible), NOT 402 (which would reveal that Pro+ is the threshold for the guarded feature, leaking information about the feature's existence and tier requirement). This ordering rule is now codified as fence row #14: "Workspace-scope BEFORE tier-gate in dependency order." Reference: S20-0 AC-5.3, fence #14.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: high`
**4-story AP17-C1 two-gate close streak (S19-0 / S19-1 / S19-2 / S20-0) — every story closed in exactly 2 passes.** S20-0 achieved REVIEW: Approve on Pass-2 after addressing 2 BLOCKING, 2 CRITICAL, and 9 MAJOR/MINOR findings in a focused review-fix pass. **[PATTERN]** `IMPACT: standards_update` `SEVERITY: high`
**SubprocessorChanged automation via YAML edit alone — zero new code required.** Adding a sub-processor to `infra/sub-processors.yaml` automatically triggers: (1) CI `validate-sub-processors-yaml`, (2) CI `enforce-subprocessor-advance-notice` (≥30-day effective_date), (3) `publish-subprocessor-changed-event` on merge to main → `subprocessor_consumer.py` fan-out → locale-aware DPA emails to all paid admins. S18-2 wired this pipeline; every subsequent epic that adds a sub-processor (starting with S20-0 + Delighted) benefits at zero code cost. The total investment: one YAML entry + running the changelog regenerator. Reference: S20-0 AC-7, infra/sub-processors.yaml, S18-2 `subprocessor_consumer.py`.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: medium`
**Module-level dispatch patch targets documented in module docstring — testability contract.** `nps_feedback.py` lines 19-28 declare, in the module docstring, the explicit patch targets for unit testing: `client_api.api.v1.nps_feedback.send_email` and `client_api.api.v1.nps_feedback.redis_client`. Module-level import with `try/except ImportError` guard ensures the symbol is patchable even in environments where the notification package is not installed. This is the canonical form for all dispatch modules that make Celery/Redis calls from within route handlers. Reference: S20-0 `nps_feedback.py` module docstring; Pass-2 B-1 fix note.

**[PATTERN]** `IMPACT: standards_update` `SEVERITY: medium`
**`_set_no_store_headers(response)` called as FIRST line of endpoint — defensive cache-control.** Both POST and PATCH handlers call `_set_no_store_headers(response)` before any business logic, which sets `Cache-Control: no-store` + `Vary: Authorization`. This ensures that even on 4xx/5xx error paths, the response headers are correct (user-specific bucket/routed_to data is never shared across tenant caches). The S19-1 H12 carry-forward is now a project-wide reference implementation. Pattern for all new endpoints returning user-specific data: `_set_no_store_headers(response)` as the first line. Reference: S20-0 `nps_feedback.py` lines 267–276; Pass-2 C-2 fix.

**[ANTI-PATTERN]** `[ACTION]` `IMPACT: prompt_adjustment` `SEVERITY: high`
**AP20-A2: DEFERRABLE INITIALLY DEFERRED constraint trap — `IntegrityError` fires at COMMIT, not flush.** Migration 071 declared `UNIQUE (sdk_response_id) DEFERRABLE INITIALLY DEFERRED`. The Pass-1 implementation relied on catching `IntegrityError` in the route handler to map it to 200 (dedup). This is structurally broken: with a deferred constraint, the error fires at transaction COMMIT, which occurs after the ASGI framework has already returned the response. The route handler's `except IntegrityError` clause is unreachable for deferred violations. Fix: add to dev-story template — "For DEFERRABLE INITIALLY DEFERRED unique constraints, use a pre-INSERT SELECT to short-circuit. Never rely on catching IntegrityError from the route handler — it fires post-flush, after the response is sent." Reference: S20-0 D-17, nps_feedback.py lines 315–326, Pass-2 m-2 resolution.

**[ANTI-PATTERN]** `[ACTION]` `IMPACT: prompt_adjustment` `SEVERITY: medium`
**AP20-A3: Frontend `User` store type not extended when backend model is extended — disclosure modal silently re-renders forever.** S20-0 Pass-1 added `users.nps_disclosure_seen_at` to the DB model and plumbed it through the API, but did NOT add `nps_disclosure_seen_at?: string | null` to the `User` interface in `frontend/packages/ui/src/lib/stores/auth-store.ts`. Consequence: the disclosure modal evaluated `user.nps_disclosure_seen_at === null` and it was always `undefined` (not null) — never dismissed, re-rendered on every workspace mount. Fix: add to dev-story template — "If this story adds a column to `client.users`, verify whether the frontend `User` type in `auth-store.ts` must also be extended. Source-inspection test must assert the new field is present in the TS interface." Reference: S20-0 Pass-1 B-2, auth-store.ts:21 fix.

**[ANTI-PATTERN]** `[ACTION]` `IMPACT: prompt_adjustment` `SEVERITY: medium`
**AP20-A4: Spec endpoint path diverged from implementation path — `NpsDisclosureSeenResponse` endpoint spec says `/api/v1/users/me/...` but implementation mounts at `/api/v1/auth/me/...`.** AC-3.5/AC-3.6 specified `POST /api/v1/users/me/nps-disclosure-seen`; implementation mounts the route on the auth router at prefix `/auth`, making the actual path `POST /api/v1/auth/me/nps-disclosure-seen`.
