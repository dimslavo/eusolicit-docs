## Part 3: Epic 19 Specific Findings — new project-context rules

### Discoveries That Change Project-Context

**Discovery 1 — CurrentUser JWT scope.**
`CurrentUser` does NOT carry `workspace_id`. The JWT for ordinary auth encodes `(user_id, company_id, role, subscription_tier)` only. `ExternalCollaboratorPrincipal` is the only principal type with `workspace_id`. All trigger sites and workspace-scoped service calls must derive workspace context from path params (e.g., `workspace_id: UUID = Path(...)`) or ORM FK lookups on the resource being written — never from `current_user`.

**Discovery 2 — WeasyPrint thread timeout recovery.**
The correct async wrapper for `weasyprint_renderer` calls is: `loop.run_in_executor(_PDF_EXECUTOR, fn, *args)` + `asyncio.wait_for(fut, timeout=N)`. On `asyncio.TimeoutError`: call `_PDF_EXECUTOR.shutdown(wait=False, cancel_futures=True); _PDF_EXECUTOR = None` so the next call rebuilds a clean pool. Do NOT use `concurrent.futures.wait + future.cancel()` — `cancel()` cannot interrupt a running WeasyPrint thread and the executor slot is never freed.

**Discovery 3 — Shared report templates.**
Any PDF/HTML template rendered by two or more services must live in `packages/eusolicit-common/src/eusolicit_common/report_templates/<template>/` and be loaded from disk in all rendering paths. Embedding the template inline in one service's source is prohibited — byte-level output divergence is guaranteed.

**Discovery 4 — chord for fan-out Beat tasks.**
Any Celery Beat task that fans out to per-workspace subtasks AND needs to track `total / succeeded / failed` counts must use `chord(group(...subtasks...), callback.s())`. `apply_async` fan-out with no callback makes aggregate result collection structurally impossible (parent returns before any child runs).

**Discovery 5 — S3 content-hash dedup.**
`head_object` dedup gates must compare `Metadata['content-hash']` to the newly-rendered content hash. Existence-only checks cause audit trail divergence when content changes between re-runs.
